# Discovering prepared voice states on connection

Prepare voice fixtures before opening the bot's Gateway connection to model
users who were already in voice or streaming before the bot started.
Create the bot, guild, voice or stage channel, and member identities first using
the [test API](test-api.md), then call the shared voice-state fixture operation:

```bash
curl -X PATCH http://localhost:3000/_test/guilds/GUILD_ID/voice-states/USER_ID \
  -H 'Content-Type: application/json' \
  -d '{
    "channel_id": "VOICE_CHANNEL_ID",
    "self_stream": true,
    "self_video": false,
    "emit": false
  }'
```

`emit: false` prepares history silently, including when a Gateway session is
already connected. Discovery does not require a live `VOICE_STATE_UPDATE`.
Use `self_stream: false` for a voice-only user. The fixture operation also
supports the other voice flags; omitted values preserve existing state.
Session IDs are generated by Fauxcord, retained through moves and flag changes,
and replaced when a disconnected user rejoins.

Connect with IDENTIFY and the `Guilds` intent. After READY, Fauxcord sends a
`GUILD_CREATE` for each guild belonging to the bot's setup. Its `voice_states`
array contains saved connected states, preserving channel, user, session IDs,
`self_stream`, and the other voice flags. Each voice user's existing identity
is included in `members`, even when it falls beyond the usual first 1,000
members. Bot and human identities keep their stored `user.bot` value.

The [Discord GUILD_CREATE contract](https://docs.discord.com/developers/events/gateway-events#guild-create)
uses partial [voice state objects](https://docs.discord.com/developers/resources/voice#voice-state-object)
without `guild_id`; use the enclosing guild's `id`. Only states with a current
membership, user, and voice or stage channel in that guild are included.
Disconnected states (`channel_id: null`), removed members, deleted users or
channels, and states pointing into another guild do not appear. With no
connected states, `voice_states` is an empty array.

A new socket using fresh IDENTIFY receives a new snapshot of saved state,
including changes prepared while an earlier connection existed. This is
distinct from RESUME, which follows the existing replay behavior and does not
rebuild `GUILD_CREATE` snapshots.

`POST /_test/reset` clears voice fixtures while retaining bot, guild, channel,
and member registrations. A nonempty `token` limits cleanup to that setup's
guilds; an omitted or empty token clears all voice fixtures. Deleting a setup,
guild, channel, user, or membership removes its affected voice fixtures.
Recreating deleted setup IDs does not restore the previous states. Unrelated
setups keep their fixtures after scoped cleanup.

These fixtures represent voice connection metadata and stream status. They do
not provide audio or video transport.
